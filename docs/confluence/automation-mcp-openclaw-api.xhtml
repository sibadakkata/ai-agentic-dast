When to use this page

If you drive the scanner from MCP, OpenClaw, or the REST API and need scan IDs, polling, and what happens after a Web UI user approves a paused scan.

Scan IDs — what they are and how to get one

Every launch returns one stable id for the whole job: scan_YYYYMMDD_HHMMSS_abcdef (six random hex chars). You get it from POST /api/v1/scans or POST /api/scan (scan_id in JSON), MCP start_scan / launch_scan, OpenClaw test_skill.py scan (printed as Scan ID), or the Web UI scan list (grey id on each row). Use that same id for all polling and results — approval does not mint a new scan.

After UI approval — your scan resumes automatically

When a Web UI user (SSO) approves a paused scan, the scan resumes on the same scan_id server-side. Automation does not need to call approve or resume — keep polling the existing scan_id for progress and findings.
  • Approve raises budget_cap_usd, sets budget_status to approved, clears the pause flag, and sets scan status back to running.
  • How to tell it resumed: GET /api/scans/{scan_id}/budget — budget status leaves awaiting_approval; GET /api/scan/{scan_id} — status is running and progress grows again.

Triggering a new scan from automation

Auto-mode launches from API/MCP/OpenClaw always use the server default cap ($30 USD unless ops changes AUTO_MODE_DEFAULT_BUDGET_USD). Manual mode is unchanged. Custom caps require launching from the Web UI (SSO).

What is not possible from automation

  • Setting or changing a budget cap (Web UI / SSO launch only; automation Auto scans use the $30 default).
  • Approving a paused scan (POST .../budget/approve returns 403 for Basic Auth).
  • Stopping at the budget gate (POST .../budget/stop is SSO-only).

General scan cancel via POST /api/scan/{id}/stop still works with Basic Auth — see the repo REST guide.
